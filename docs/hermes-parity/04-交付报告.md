## 五、本轮修掉的真缺陷

| 级别 | 缺陷 | 修复 | 回归测试 |
| --- | --- | --- | --- |
| P1（逻辑官） | 并发批不记「验证」：写后同轮读回仍被判未验证，白烧一轮且向用户说假话 | 唯一记账入口 `runToolState.recordStep`，串行/批共用 | `TestParallelBatchRecordsVerification` |
| P1（逻辑官） | 被预算拒绝的调用仍被执行，结果又覆盖成「未执行」 | 先逐个占预算，只把占到的放进批 | `TestParallelBudgetRejectionDoesNotExecute` |
| P2（逻辑官） | 取消后仍可能启动新调用 | 拿到并发令牌后再查一次 `ctx.Err()` | 并发用例全绿 |
| P1（审计官） | 默认 eino 执行器下 `AGENT_TOOL_PARALLEL=read` 静默失效，状态接口却回显配置值 | 新增 `parallelEffective()`，接口同时回显配置值与生效值，启动日志明说「配了但未生效」；不强行给 eino 开并发（共享 state，会竞态） | `TestParallelEffectiveMatchesEngine` |

## 七、已知边界与后续（按收益排序）

1. **结构标准化只做了一半**：`web` 44 文件/13,080 行/64 路由，架构官给了同包拆文件方案（零 import 变化 + 行数守恒验收）。本轮只删了一处死码（`resolveCommandWorkingDir`），**拆文件暂缓**——理由是与 evolve 收尾同窗口，风险不对等。方案在架构官的 `structure-plan.md` §9。
2. 技能仍存 MySQL（契约 §1.7 不加迁移），因此「技能文件化 + 旁车账本」未做；回滚靠 `journal.jsonl` 记录改前/改后，而不是文件树。
3. MCP 只做 stdio；HTTP/SSE 传输与 `tool_describe` 第二桥接留待工具有上百个时再加。
4. 并行按路径切段（写与同路径读写互斥）未做，当前只按风险切段。
5. per-turn 结果总预算（200k 字符）未做，单条落盘已覆盖当前量级。
