# 持久执行对话与 Router

主会话在工作、代码和学习用途下提供 `orchestrator_route`；计划档和执行子会话不提供。
它复用既有团队服务、子任务记录、消息表与后台执行器，不需要新数据库表。

## 使用

在聊天中选择“辅助工作”或“代码协作”。需要自主修改与验证时选择“自主执行”；确认档的执行成员仍不能绕过风险操作限制。

例如：

> 把页面实现交给一个独立执行对话。保留目标和验收要求，完成后检查结果；需要修改时交回原对话继续。

Router 的模型工具协议：

```json
{"action":"list"}
{"action":"accept","target":"page-worker","title":"页面实现","message":"完成页面；约束……；验收……"}
{"action":"attach","target":"page-worker","message":"在现有结果上修复……，重新运行验证"}
```

`accept` 创建具名执行对话；同名任务使用 `attach`。消息投递成功仅表示受理。
现有团队面板和子任务接口展示执行状态；结束报告回到主对话。主对话忙时排队等待唤醒。
Router 仅能管理当前用户、当前主会话的成员，不能访问任意其他历史聊天。

## 长历史

执行对话续跑时接入 `agent_compact.go` 的滚动摘要。原始消息仍保存在数据库，只有模型输入被压缩。
复用旧摘要时，未被摘要覆盖的新消息必须保留，不能只保留最近窗口而丢掉中间几条。
完整执行结论保存在执行对话；父会话通知和任务卡只携带截短报告，避免主对话膨胀。

## 自动完成的边界

自主档已有 `LimitRecoveryRounds` 提供限额内的续行。主会话接到报告后，指令要求对照原任务验收，未完成则继续处理或交回原成员。
这不是独立的宿主验收器：模型自然结束仍会结束该轮，不能保证任意任务无限自动推进。
后台主会话唤醒仍受每小时 6 次、最短 30 秒的现有保护限制；触发限流时报告保存在历史中。
进程重启后的自动补投、正在运行任务恢复和任意已有聊天的接管，不在此实现范围。
需要宿主持续推进、逐项验收并能在重启后恢复的工作，请使用长任务（`task_manage`，见 `16-task-runtime.md`）。

## 验证

`go test ./internal/web ./internal/agent ./internal/agent/toolsys/...`

`TestSessionRouterPersistentConversation` 使用临时 SQLite 与确定性模拟模型验证创建、原对话续跑、完整历史和结果、用户隔离及主/子角色边界；不访问真实模型供应商。
自动模式预算续行沿用 `internal/agent/budget_test.go` 的验证。
