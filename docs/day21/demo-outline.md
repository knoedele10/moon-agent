# Day 21 演示提纲（四段结构）

- 时长目标：3 分钟（对应余力加练的演示视频）
- 演示地址：https://blog-my-check-10974.app.workbuddy.host
- 一句话定位：一个自己搭的多模型对话站，外加一个能看到真实数据的公网检查台。

## 第 1 段：用户问题（0:00–0:30）

- 场景：想同时用 DeepSeek / OpenAI / 通义等多个模型，就得在多个网页之间来回切，key 也散在各家后台；想比较同一个问题的回答，只能复制粘贴。
- 三条具体痛点：
  1. 切换成本高：换模型 = 换网站 + 重新贴上下文。
  2. key 管理散：看不到"哪些模型已经配好 key、哪些还没配"。
  3. 数据不是自己的：对话、收藏、热搜都在别人手里，想留一份自己的记录很麻烦。
- 我要做的：一个自己的客户端 —— 多模型可切、key 自己管、数据自己存；并且放到公网上，任何人点开链接就能验证。

## 第 2 段：核心流程（0:30–1:40）

按"点开链接就能自己走完"的顺序演示：

1. 打开 https://blog-my-check-10974.app.workbuddy.host/ —— 检查台首页。
2. 看"服务健康"卡片：绿点 + 服务正常（version: mock-1）。
3. 看"今日热搜（真实数据）"：20 条，来自微博 / 知乎 / 百度快照（fetched_at 2026-10-03）。
4. 看"我的收藏"：9 条真实数据。
5. 现场写一条收藏（POST /api/favorites）→ 刷新页面看到新增 → 证明真实读写，不是静态假数据。
6. 进 /hot 热搜页、/chat 对话页：hash 路由多视图、侧栏会话筛选、模型视图标出"未配置 Key"。
7. （可选）本地打开同一份前端，请求公网 API 成功 —— 证明 Day 20 的 CORS 配置生效。

## 第 3 段：提示词改写（1:40–2:30）

这一周把提示词从"许愿"改写成"带验收标准的工单"。三组前后对比：

| 改写前（许愿式） | 改写后（工单式） | 结果差异 |
|---|---|---|
| 帮我做一个热搜页面 | 在 deploy/public 下新增 hot.html：读 GET /api/hot 渲染列表，每条显示 rank/title/heat/platform；失败时显示"加载失败"；必须能在公网 /hot 打开并返回 200 | 一次成型，验收时直接拿链接对，不用来回猜 |
| 接入 Ollama | llm 层按 Backend 工厂注册：openai/claude/gemini/ollama/mock 五个后端；ollama 走 http://localhost:11434 且无需 key；新增端点不得改调用方代码 | 重构边界写清楚，19 个文件一次改完 |
| 帮我修一下收藏重复提交 | POST /api/favorites：同 title 返回 409 + 中文错误；缺 title 返回 400；非法 JSON 返回 400；三条都要有可复现的命令证据 | 三条边界都能被第三方复验，而不是"我试过了" |

三条改写规则：

1. 说清输入 / 输出 / 边界，别只说"做一个 X"。
2. 把**验收标准写进提示词**：标准必须能被别人打开验证（URL、状态码、文件）。
3. 明确"不许做什么"：不改接口契约、不引新依赖、不动无关文件。

## 第 4 段：验证方式（2:30–3:00）

- 证据链五层：HTTP 状态码 → 交叉验证脚本（scripts/verify-day21.ps1，15/15 PASS）→ 无头浏览器 DOM 渲染检查 → 截图 → git 提交。
- 一条命令复现：powershell -ExecutionPolicy Bypass -File scripts/verify-day21.ps1 -LogPath docs/day21/verify-log.txt
- 缺项照实说：真人用户测试未做（FAIL）、Ollama 运行时未复验（FAIL）、演示视频未录（未执行），全部写在 acceptance.md 第二节。
