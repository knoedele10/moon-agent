# Day 28 · 结营复盘：28 天，我最大的一个认知改变

> 作品：blog-my v1.0 —— 一个「多模型 AI 对话 + 收藏 + 热搜」应用，
> 既有桌面端（Electron，主交付），也有可公网访问的演示版。

## 一句话

**我以为"做出来"就是完成，28 天后我才知道：只有"可被当场验证"才算完成。**

## 为什么是这个改变

这不是一句口号，是被这 28 天里的几次"打脸"砸出来的——而且每次都来自我以为最稳的地方：

- **Day 26**：我以为公网上跑的是最新代码，一查才发现它已经比仓库落后两天——"部署过"不等于"部署的是这一版"。
- **Day 27**：我以为发消息"没反应"是小事，一查才发现服务器把一个**没实现的接口返回了 HTTP 200 + 登录页 HTML**，前端看见 200 就以为成功了。状态码会撒谎，只有看响应内容才知道真相。
- **Day 28**：我以为桌面端安装包是现成的，一查才发现它**比主程序旧了 5 天**；我以为"能双击启动"是废话，结果在沙盒里启动即退出——**最后一步"跑起来"恰恰是我没法替用户验证的**。

这三次的共同点：**完成感会骗人，证据不会**。所以我整个第 4 周的收获，都收敛到一件事上——

> **把"做完"改成"可验证"**：每一项都要有能当场打开的东西、能复现的命令、能对上的版本号；验证不了的，如实标"未完成"，而不是假装完成。

## 它具体改变了我的习惯

1. **先信证据，再信感觉**：写代码前先问"我怎么证明它是对的"，而不是写完再说。
2. **版本要对得上**：构建产物、线上代码、仓库提交，三者必须能互相指认——今天就是靠 `allow-methods` 里没有 PATCH/DELETE 才发现线上是旧版本。
3. **错误信息也是产品**：一个误导性的报错（"模型未返回内容"）比没有报错更糟，它让用户以为是自己的错。
4. **承认做不到也是一种交付**：AI 不能替用户拉来一个真人试用、也不能在沙盒里双击桌面程序——把"我验证不了"写清楚，比伪造一张截图更有价值。
