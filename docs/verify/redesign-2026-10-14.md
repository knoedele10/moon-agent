# 对话页改版：排版对齐参考图 + 蓝/深色双主题

日期：2026-10-14　范围：前端（`templates/`），无 Go 改动。

## 为什么改

用户发来一张参考截图（Cyrene 桌面端）要求「前端排版参考这个」。参考图的可取之处是四件事，
这次按这四件事重排，顺手把配色体系做成可切换的两套主题：

1. 顶部**居中**的四模式分段胶囊（对应我们已有的 Chat / Work / Code / Learn 四种会话模式）；
2. 左栏带图标的功能导航 + 左下角账号块；
3. 首屏是「招呼 + 大输入框」作为一组垂直居中，而不是输入框孤零零吊在窗口底部；
4. 右上角常驻一块浮动的「当前任务」卡片。

## 布局改动

| 位置 | 之前 | 现在 |
| --- | --- | --- |
| 顶栏 | 左标题 + 右模型/密钥/设置/退出，底边线 + 实色底 | 三列网格：左标题、**中间四模式胶囊**、右模型 + 主题开关 + 密钥；无底边线 |
| 侧栏 | 纯文字导航 | 每条导航带 lucide 内联图标；底部新增账号块（头像 + 用户名 + 设置 + 退出） |
| 首屏 | 中央一个「AI」方块 + 一句提示，输入框在底部 | 月牙标记 + 星点 + 「让小月来帮你把今天的事做完」（名字带淡蓝底），**招呼与输入框一起居中** |
| 输入框 | 一行塞下工作区 / 档位 / 助手 / 模式 4 个控件 + 发送键 | 两行：上面写正文，下面一排胶囊（工作区 / 档位 / 助手 / 参数）+ 圆形发送键；再下面一行是工作目录与免责声明 |
| 会话模式 | 输入框里的下拉 | 顶栏胶囊（真状态仍是隐藏的 `#kind-select`） |
| 新组件 | — | 右上角「当前任务」卡片：模式徽标 / 工具进度 `done/total` / 当前会话 / 工作区 |

首屏居中用 CSS 实现（`.app.is-empty` 时给 `.messages` 一个 `margin-top:auto`、给 `.composer` 一个
`margin-bottom:auto`，flex 会把剩余空间平分给这两个 auto 边距），不动 DOM 顺序，也不影响消息流。

## 主题与 token

- 颜色全部收敛到两个块：`:root`（浅色 `azure`，**默认**，蓝色重音 + 冷调白底）与 `:root[data-theme="graphite"]`（升级前的石墨深色，原样保留）。
- 浅色主题原本叫 `sakura`（粉色），用户要求改成蓝色底后重命名为 `azure`；`theme-boot.js` 里做了旧键兼容，
  存过 `sakura` 的人不会被默默丢回默认值。
- 半透明叠加统一成三通道变量（`--accent-rgb` / `--danger-rgb` / …），组件里写 `rgb(var(--accent-rgb) / 0.12)`，
  这样同一套透明度在两个主题下都能复用——`rgba()` 里塞不进 `var()`，这是唯一可行的写法。
- 切换开关在顶栏（`#theme-toggle`），选择存 `localStorage['blogmy:theme']`；首帧由 `theme-boot.js`
  在 `<head>` 里阻塞执行，避免深色主题先闪一帧浅色。五个页面（对话 / 设置 / 登录 / 注册 / 错误）都挂了它。
- 对比度是算过的：浅色下 `--accent #2563eb`（对白底 5.17，白字压它也是 5.17）、`--text-muted #56626f`（≈6.2）、
  `--text-faint #6b7787`（4.55）。小字号的状态文字（胶囊标签、导航选中项）因此不会发虚。
- 重音已经是蓝的，所以 `--info` 特意挪到偏青的 `#0f7490`，否则信息色和主色分不出来。
- `.select` 的 `color-scheme` 改成 `inherit`：原来写死 `dark`，浅色主题下原生下拉箭头会是深色的。

## 与既有实现的接缝（重要）

- **`#kind-select` 仍然是唯一状态源**：`chat.js` 读它取 `kind`、按会话记住模式也挂在它的 `change` 上。
  顶栏胶囊只是同一份状态的另一个视图（`kind.js` 双向同步）。后端协议、发送逻辑、会话切换一行未改。
- `#kind-select` 用 `hidden` 移出无障碍树，避免读屏读到两份模式选择。
- `chat.js` 只加了四类小钩子：`setEmptyState()`（hidden + `is-empty` 一起改）、`notifyTaskCard()`、
  `refreshKindSelect()` 里同步胶囊、工具事件出口记一次进度。
- 「当前任务」卡片渲染在独立文件 `static/js/taskcard.js`（`window.TASKCARD`），不改 chat.js 的渲染逻辑。
- 参数面板 / 提示词快选是 `chat.js` 注入到输入框里的，改版后位置不变（都在 `.composer` 内绝对定位）。

### 已知限制

- 本机 Chrome 在沙箱里起不来（mojo IPC 被拒），所以**没有像素级截图**：上面的验证是 jsdom 的 DOM 级验证，
  CSS 只做了「解析无报错 + 括号平衡 + token 双向覆盖」的静态检查，视觉效果仍需人眼确认。
- 「当前任务」卡片在窗口宽度 < 1180px 时隐藏（它是浮层，窄窗口会盖到正文上）。
- 最后一次跑 `verify-redesign.cjs` 时模型侧返回 **402 Insufficient Balance**，G 那条（真实发消息）走了 SKIP；
  在同一台机器上更早的两次运行里，G 是用真实模型跑通的（模型回了 111 字的正常回答）。

### 改版中抳出来的一个真 bug

「参数」按钮是 `chat.js` 运行时注入的。它原来的插入逻辑是「插到发送键前面，插不了就 append 到 form」；
改版后发送键住进了 `.composer-toolbar`（不再是 form 的直接子节点），所以它会走 append 分支，
而 form 现在是竖向 flex——这颗胶囊会单独占一行，看上去像颗掉出来的孤儿。
已修：优先插进工具条，并保留旧结构的兼容分支；`verify-redesign.cjs` 的 H 条就是钉这个的回归。

## 第二轮：胶囊下拉 + 页内对话框（同日追加）

用户反馈两件事：一是「自主执行 / 不使用助手」这两个下拉的框子太原生，二是改工作目录时报
`prompt() is not supported`。两件事同一类病：用了系统控件。

**1. 原生 select → 胶囊下拉（`static/js/chipselect.js`）**

- 原生下拉是系统控件，样式完全不受 CSS 控制（内嵌浏览器 / Electron 里尤其突兀）。
- 做法和四模式胶囊一致：**select 仍是唯一状态源**，只是用 clip 手法藏起来，前面放一个
  可完全掌控外观的按钮；选项列表是页内浮层（`role=listbox`），位置不够时自动往上翻。
- 两个实现细节值得记：`select.value` 被代码直接赋值时没有任何事件可听，所以劫持了一次
  setter（否则模型列表异步加载完、切会话恢复模型时按钮文字会停在旧值）；选项列表变化靠
  MutationObserver（模型列表是异步填的）。
- 覆盖范围：输入框那排的 `#mode-select` / `#assistant-select`，加顶栏的 `#model-select`。
- 键盘可达：Enter / 空格开关、方向键移动、Esc 关闭、Tab 收起；按钮带 `aria-haspopup` /
  `aria-expanded`，选项带 `role=option` / `aria-selected`。

**2. `window.prompt` → 页内对话框（`static/js/uiask.js`）**

- 根因：**Electron 从未实现 `window.prompt`**（调用只会打印 `prompt() is and will not be supported`
  并返回 null），所以桌面端和内嵌浏览器里点「工作区」一点反应都没有。
- 新增 `UIASK.prompt()` / `UIASK.confirm()`（Promise 风格），用原生 `<dialog>` 渲染；
  jsdom 没实现 `showModal()`，所以两条路都留（抛了就退化成 `open` 属性）。
- `chat.js` 里两个 `window.prompt`（工作目录、重命名会话）全部换掉，另两个 `window.confirm`
  （删会话、删消息）一并换成页内样式；其余文件里的 `confirm` 保持不动（它在 Electron 里能用）。

验证：`verify-redesign.cjs` 加了 I / J / K 三条——I 验胶囊下拉开合与写回 select，
J 验对话框能拿到输入且取消返回 null，K 是静态检查（`chat.js` 里不允许再出现 `window.prompt`）。
全量 12 条断言 0 失败；`verify-ui.cjs` 仍然 30 通过 / 0 失败。
