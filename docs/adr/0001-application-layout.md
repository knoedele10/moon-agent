# ADR-0001：应用入口与内部模块布局

- 状态：采用
- 日期：2026-10-19

## 背景

项目是 Electron 桌面应用加 Go HTTP 服务，原来可执行入口、业务包、示例与临时文档混在根目录。两个运行器各自维护工具执行保护，容易在修复时发生行为漂移；构建脚本也有重复构建和个人依赖路径。

## 决策

1. `cmd/blog-my`、`cmd/skillimport` 保存可执行入口；应用组装放入 `internal/app`。
2. HTTP、运行器、模型、持久化和记忆放入 `internal/{web,agent,llm,model,rag}`。保留现有包名以控制迁移范围。
3. Eino/legacy 保留独立协议 Adapter，通过共享工具状态集中安全规则；不删除仍承担回退与对照验证职责的运行器。
4. 页面资源、CUA 和 Electron 沿用发布资源协议。独立示例归入 examples，用户文件归入 artifacts，旧任务归入 docs/archive。
5. 构建只编译规范入口一次；依赖由锁文件安装，缓存与临时产物落在 build 并隔离主模块扫描。

## 结果

入口、源码、示例与生成内容可直接定位；内部包无法被外部 Go 模块误用为稳定 API。执行保护获得更好的 Locality，跨引擎回归在真实的两个 Adapter 上验证 Interface。未来按明确业务需求继续拆分 web 中的功能，不为目录形式增加无行为的转发层。

## 限制

这是应用级目录整理和有证据的热点优化，不构成全部业务的重新设计。现有数据库 AutoMigrate 与全局连接仍保留；向量检索仍是应用内扫描，若规模或多实例需求变化，应另作迁移和索引决策。
