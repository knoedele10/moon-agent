## 四、本次最高优先级修复（P0）

**根因**：部署版 `server.js` 没有 `/api/chat` 路由，请求掉到最下面的"页面兜底"，把登录页 HTML 连同 HTTP 200 一起返回。前端看到 200 就当成功，把 HTML 当 SSE 流解析，一行 `data:` 都读不到 → 只显示「模型未返回内容」。

**修复（最小改动，不加功能）**：未实现的 `/api/*` 一律返回 **JSON 404 + 中文说明**，不再返回假 200。

**修复前后对比**（真实实测）：

| | 修复前 | 修复后 |
|---|---|---|
| POST /api/chat | HTTP 200 + text/html（登录页） | HTTP 404 + application/json |
| 用户看到 | 「（模型未返回内容）」（莫名其妙） | 「接口不存在或未启用：POST /api/chat（当前部署版是 mock 服务，对话接口未接入真实模型）」 |

**验证**：本地 16 项断言通过 15（唯一"失败"项是上面 P1——已知 UI 缺口，今日不修）；公网重新验证同样 15/16，回归接口全部正常。详见 `day27-verify.js` 输出。

**本次故意不修的**（遵守"今日不做：按反馈大改；加新功能"）：
- P1 收藏添加入口 —— 属于新功能，留待后续
